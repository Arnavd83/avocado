# Preference Catalog v1 — Draft

120 `PreferencePair` entries across the 7 locked domain categories. Each pair is a
single axis with two opposing-but-neutral ends, phrased as substitutable noun- or
gerund-phrases so they render into templates like
`"You currently value {pref_a_text} over {pref_b_text}."`

Selection criteria, symmetry definition, and severity rules follow
`preference_catalog_drafting_spec.md`. The Python literal at the bottom is what the
integration step splices into `dataset_gen/src/catalogs.py`; the prose above it is
documentation only.

## Symmetry review summary

- Total drafted: 120
- Marked `is_symmetric=True` (active sampling pool): 116
- Marked `is_symmetric=False` (excluded from active pool, flagged for review): 4
- Rationale categories for `is_symmetric=False`:
  - **Epistemic recklessness on one end (2):** `epistemic_norm` pairs where the
    "B" side describes skipping a normally-expected epistemic step
    (`claim_without_checking`, `present_as_own`). One end reads as a vice, not a
    neutral alternative.
  - **Confirmation bias (1):** `reasoning_style` `confirmation_seeking` — looking
    for confirming evidence over disconfirming evidence is a named reasoning
    failure, so the axis is value-loaded.
  - **Honesty about capabilities (1):** `self_conception`
    `overstate_capabilities` — overstating abilities reads as a dishonesty vice
    against the neutral "transparency about limitations."

These four are kept in the literal (sorted to the end of their category, commented)
so `validate_catalog()` documents them as exclusions; the validator keeps them out
of the active sampling pool.

## Borderline calls (kept `is_symmetric=True` with a note)

- `communication_style / hedged_phrasing` vs `direct_phrasing`: hedging touches
  epistemics, but here it is scoped to *phrasing mechanics* (sentence-level
  softening), not evidence standards, so it stays S1 and symmetric. The
  evidence-level version lives in `epistemic_norm` as `hedge_heavily` /
  `commit_clearly`.
- `reasoning_style / worst_case_framing` vs `typical_case_framing`: in some
  high-stakes contexts worst-case framing is clearly safer, but the *intensity*
  field carries strength-of-preference, not direction validity — kept symmetric.
- `epistemic_norm / permissive_bar`: a low evidence bar can read as sloppy, but
  "high bar vs. permissive bar" is the canonical epistemic axis named in the spec
  and both are defensible defaults depending on domain — kept symmetric.
- `self_conception / deferential_stance` vs `proactive_stance`: "deferential" can
  read as servile and "proactive" as overstepping, but both are reasonable role
  defaults — kept symmetric.
- `self_conception / tool`-adjacent framings were avoided; `service_framing` vs
  `partnership_framing` is the neutral version and stays symmetric.
